# البنية التقنية المقترحة

## قرار التشغيل

أكد المستخدم يوم 2026-09-27 أن الاستخدام لشخص واحد على جهاز واحد. نبني تطبيق Windows محليًا يعمل دون إنترنت، بقاعدة SQLite على القرص المحلي. لا خادم شبكي ولا استضافة مدفوعة ولا اشتراك AI مطلوب للحسابات. لا تبدأ مشروع Sites أو موقعًا مستضافًا لأن المنتج هنا برنامج مكتب محلي.

## مكونات التطبيق

| المكون | الاختيار المبدئي | الغرض |
|---|---|---|
| تطبيق ويندوز | Electron | نافذة التطبيق وحوار الملفات والطباعة وPDF |
| الواجهة | React + TypeScript + Vite | واجهة عربية وإدخال جماعي قابل للصيانة |
| البيانات | SQLite، موصل better-sqlite3 مبدئيًا | معاملات محلية وتخزين بسيط؛ اختبار توافق الوحدة مع Electron قبل تثبيتها |
| الحساب | وحدة TypeScript مستقلة تستخدم decimal.js | نتائج عشرية حتمية بنفس القواعد في كل المخرجات |
| Excel داخل المنتج | ExcelJS مبدئيًا | استيراد وتصدير XLSX؛ اختبار العربية والتنسيق وإعادة القراءة |
| PDF | Electron webContents.printToPDF | نفس قالب HTML/CSS المحلي المستخدم للطباعة |
| التحقق | Zod مبدئيًا | مدخلات ورسائل اتصال مقيدة |
| الاختبارات | Vitest للوحدات، Playwright لمسار التطبيق | الحسابات والاستيراد ومسار الشهر والتصدير |
| التوزيع | مثبت Windows عبر Electron Forge مبدئيًا | تثبيت محلي وترقيات مع حفظ البيانات |

الاختيارات تصميمية وليست مكتبات مثبتة. في المرحلة الأولى تُراجع الإصدارات المستقرة المتوافقة وتراخيصها وتثبت في lockfile. لا تعتمد أرقام إصدار متخيلة ولا تغيّر التقنية دون توثيق السبب. إن احتاج موصل SQLite بناءً أصليًا، أثبت نجاح الحزمة على Windows مبكرًا قبل تطوير الشاشات.

Electron يوفر الطباعة وPDF من webContents؛ تفاصيل الخيارات تُراجع في [الوثائق الرسمية](https://www.electronjs.org/docs/latest/api/web-contents). العزل بين الواجهة والنظام وضوابط النوافذ تتبع [دليل أمان Electron](https://www.electronjs.org/docs/latest/tutorial/security). النسخ الحي لقاعدة SQLite يستخدم وسيلة متسقة مثل [Online Backup API](https://www.sqlite.org/backup.html). هذه مصادر القرار التقني، وليست إثباتًا لاختبار التطبيق.

## فصل المسؤوليات

واجهة React ← جسر preload محدود ← خدمات التطبيق المحلية ← محرك الحساب/قاعدة البيانات/التصدير.

الواجهة لا تصل مباشرة للملفات أو SQL. واجهات الجسر عمليات محددة مثل `employees.search` و`payroll.updateInputs` و`payroll.approve` و`exports.create` و`backups.restore`. تفحص العملية المحلية البيانات والحالة قبل كل تعديل. لا يتم تمرير SQL أو أوامر نظام أو مسار ملف حر من الواجهة.

محرك الحساب دالة مستقلة `calculatePayroll(inputs, policy)` تعيد البنود والإجماليات وشرحها وإصدارها. يعاد الحساب قبل الحفظ والاعتماد. الحساب الفوري في الواجهة معاينة؛ العملية المحلية هي مصدر الحقيقة. لا eval ولا تفسير صيغ يكتبها المستخدم.

## شكل المشروع عند التنفيذ

```text
src/main/             تشغيل التطبيق، الجسر، الملفات، الطباعة
src/preload/          واجهات محددة للواجهة
src/renderer/         الشاشات والمكونات العربية
src/domain/payroll/   حسابات وقواعد بلا اعتماد على الواجهة
src/application/      حالات استخدام الموظفين والشهور والسلف
src/infrastructure/   SQLite، نسخ احتياطي، استيراد وتصدير
src/print/            قوالب قسائم وكشوف وCSS الطباعة
db/migrations/        تغييرات مخطط البيانات المتسلسلة
tests/fixtures/       بيانات مصطنعة فقط
assets/brand/         الشعار
assets/fonts/         الخطوط المحلية وتراخيصها
docs/                 وثائق المنتج والتنفيذ
```

## البيانات والعلاقات

| الكيان | البيانات والقيود الأساسية |
|---|---|
| Employee | UUID، كود فريد، اسم، وظيفة، حالة، تواريخ، sourceCode، بيانات إضافية |
| CostCenter | كود فريد، اسم، حالة |
| EmploymentTerms | employeeId، أساسي، مركز تكلفة، طريقة دفع، تاريخ سريان؛ يمنع تداخل الفترات |
| PaymentDetails | بنك وحساب ومستفيد وملاحظة، منفصلة عن الاسم؛ حماية العرض |
| PayrollPeriod | سنة وشهر فريدان، الحالة، الإصدار المعتمد الحالي |
| PayrollRevision | periodId ورقم مراجعة، إصدار القواعد، تاريخ الاعتماد، سبب التعديل |
| PayrollEntry | employeeId وrevisionId فريدان معًا، لقطة بيانات الموظف والمدخلات والنتائج |
| PayrollPolicy | مقام 30، إعاشة 75، صندوق 1% وحد أدنى 50، قاعدة التأخير، التقريب، سريان |
| Advance | موظف، مبلغ أصلي، تاريخ، وصف، رصيد مشتق من الحركات |
| AdvanceAllocation | جزء مخصص لمسير معين، يمنع خصمه مرتين، يثبت عند الاعتماد |
| PaymentRecord | entryId، مبلغ مدفوع، تاريخ، وسيلة، مرجع؛ يدعم جزئي/كامل دون تكرار |
| ImportBatch/ImportRow | بصمة الملف، صف مصدر، خام، تصنيف، نتيجة، خريطة الهوية |
| AuditEvent | العملية والوقت والقيم قبل/بعد وسببها وهوية المشغل المحلي |
| ExportRecord | مراجعة المسير، قائمة الموظفين، القالب وخياراته، المسار والبصمة |
| AppSettings | الشركة، حماية الدخول، آخر مسار نسخ، تفضيلات الطباعة |

تخزين المبالغ النهائية كقروش صحيحة في SQLite، مع التحقق من الحدود. الحساب الوسيط Decimal من نصوص عشرية؛ معدلات الأيام والكميات تُخزن كنص عشري مضبوط أو وحدات صحيحة متفق عليها. لا تخزن المبالغ في REAL. تفعيل المفاتيح الخارجية والقيود ومعاملات الحفظ. الفهارس على الكود والشهر ومركز التكلفة وحالة الموظف، مع حقل منفصل للاسم المطبع للبحث.

## دورة الحالة وثبات التاريخ

مسودة ← جاهز للمراجعة ← معتمد ← مصروف جزئيًا/بالكامل بحسب حركات الصرف. لا تعديل مباشر لنسخة معتمدة. أي تصحيح ينشئ مراجعة جديدة مع سبب وربط بالسابقة ويحافظ على قسائمها. إعادة فتح نسخة مصروفة تتطلب تسوية واضحة ولا تعيد السلف للخصم مرة ثانية.

اعتماد الشهر مع تثبيت نتائج الرواتب وتخصيص السلف عملية واحدة متكاملة. إلغاء قبل الصرف يعكس تخصيص السلف بقيد موثق. تحديثات المسودة تحمل رقم إصدار لمنع استبدال قيمة أحدث من نافذة قديمة. التطبيق يعمل بنسخة واحدة، وقاعدة البيانات لا توضع في مجلد شبكة أو مزامنة مباشرة.

## السلف في النسخة الأولى

تدعم المالية إدخال مبلغ خصم الشهر مع مرجع. إن كان هناك مبلغ سلفة أصلي معروف، ينشأ سجل سلفة وجدول تخصيص شهري ورصيد. إن كان المعروف فقط هو خصم الشهر، يحفظ كخصم سلفة لذلك الشهر مع بيان أنه لا يمثل رصيدًا تاريخيًا معلومًا. لا نختلق رصيدًا أصليًا من مبلغ الخصم. استيراد تاريخ السلف لاحقًا لا يكرر المبالغ المخصومة سابقًا.

## حماية البيانات والتشغيل

- بيانات التطبيق في مجلد userData مستقل عن مجلد التثبيت؛ التحديث لا يمس القاعدة. نسخة احتياطية قبل أي ترقية مخطط.
- حماية دخول محلية بكلمة مرور مخزنة كتجزئة مملحة مناسبة، قفل تلقائي اختياري. قفل الواجهة وحده لا يشفر قاعدة البيانات؛ يجب توضيح ذلك في دليل التشغيل وتقييم تشفير الجهاز مع المستخدم عند التجهيز.
- `contextIsolation: true` و`sandbox: true` و`nodeIntegration: false`، سياسة محتوى محلية، ومنع التنقل والمحتوى الخارجي غير المسموح.
- لا اتصالات خارجية ولا تحميل خطوط وقت التشغيل. تنظيف قيم HTML، ومنع تفسير نصوص أسماء/ملاحظات الموظفين كصيغ في Excel.
- السجلات التشخيصية لا تحتوي رواتب وأرقام حسابات كاملة. التقارير الشخصية في ملفات منفصلة عن الكود، والنسخ المرجعية مستبعدة من Git.
- سجل التعديلات مفيد للمراجعة لكنه ليس ضمانًا ضد مدير نظام يملك القرص؛ لا نسميه غير قابل للعبث.

## النسخ الاحتياطي والاسترجاع

نسخة تلقائية عند أول استخدام في اليوم وقبل الاعتماد والترقية، مع احتفاظ مقترح بآخر 7 يومية و4 أسبوعية و12 شهرية، قابل للضبط. نسخة إضافية على قرص آخر يختاره المستخدم تحمي من عطل القرص الأساسي. النسخ على القرص نفسه وحده لا يكفي.

الحزمة تحتوي قاعدة بيانات متسقة والإعدادات والأصول المطلوبة ومعلومات الإصدار وبصمات التحقق. لا نسخ أعمى لملف SQLite أثناء وجود WAL نشط. الاسترجاع يتحقق من الحزمة والتوافق وسلامة القاعدة، يحفظ نسخة من الوضع الحالي، يغلق الاتصالات، ثم يستبدل بصورة آمنة. اختبار الاسترجاع على مجلد جديد وإعادة مطابقة شهر معتمد شرط إطلاق.

## الطباعة والتصدير

إنتاج المخرجات من لقطة واحدة محددة الإصدار، مع انتظار تحميل الخط والشعار. تُبنى معاينة PDF داخل التطبيق بدل الاعتماد على صفحة HTML لا تمثل الناتج. تشغيل التصدير الكبير في مهمة منفصلة مع تقدم وإلغاء، وكتابة ملف مؤقت ثم نقله للاسم النهائي عند النجاح.

Excel الرسمي يعرض نتائج النسخة المعتمدة كقيم رقمية ثابتة ومجاميع مطابقة؛ تعديل نسخة Excel لا يغير البرنامج. إن طُلب ملف حساب قابل للتحرير لاحقًا يخرج كمسودة مستقلة بمعادلات مختبرة، وليس بديلًا عن المصدر المعتمد. تتأكد اختبارات إعادة القراءة من الأرقام والتواريخ وعدد الصفوف وغياب صيغ ناتجة عن نصوص غير موثوقة.

## أهداف أداء تُقاس لاحقًا

الاختبار على جهاز Windows تُسجل مواصفاته، بيانات مصطنعة لـ1000 موظف و24 شهرًا. الهدف: بحث/فلترة P95 أقل من 300ms، معاينة حساب صف أقل من 100ms، حفظ مؤكد أقل من 500ms، إعادة حساب 1000 موظف أقل من ثانيتين، Excel لألف صف خلال 5 ثوان، PDF لمئة قسيمة خلال 15 ثانية بعد تهيئة الخطوط. هذه أهداف قبول قابلة للمراجعة بعد القياس وليست سرعات محققة. التخزين والتصدير لا يجمدان الواجهة، وتوثق أسباب أي تجاوز.
